      Business Central

      How approved orders reach Microsoft Dynamics 365 Business Central. In this prototype every request is built exactly as the API v2.0 expects and answered by a simulated sandbox, so nothing leaves the page.

      Connection
      How it avoids double orders

      1. Before sending, the inbox compares the order with every order already seen for that customer (same order number, or the same lines within the duplicate window).

      2. Before creating, it asks Business Central for a sales order with the same external document number. If one exists, nothing is created.

      3. Header first, then one request per line, so a failed line can be retried on its own.
